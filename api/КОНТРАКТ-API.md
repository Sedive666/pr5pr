# Контракт учебного API «Магазин кроссовок»

Документ описывает интерфейс, с которым работает клиент практической работы 4.
Составлен по образцу контракта «Библиотека» из методических указаний и заменяет его:
домен приложения — магазин кроссовок, а не библиотека.

Базовый адрес по умолчанию: `http://localhost:8080/api`

Реализация — `api/mock-server.js`, зависимостей нет, нужен Node.js 18 или новее:

```bash
node api/mock-server.js --port 8080 --origin http://localhost:5555
```

---

## 1. Общие соглашения

- Формат обмена — JSON, кодировка UTF-8.
- Заголовок `Content-Type: application/json` обязателен для запросов с телом.
- Идентификаторы целочисленные, начинаются с 1.
- Даты передаются строкой в формате ISO 8601: `2025-09-19T09:00:00.000Z`.
- Все ответы со списками возвращают одинаковую оболочку с постраничной разбивкой.
- Удаление логическое: запись получает `deletedAt` и перестаёт попадать в выборки.

### 1.1. Оболочка списка

```json
{
  "items": [ /* массив объектов */ ],
  "page": 1,
  "size": 10,
  "total": 26,
  "totalPages": 3
}
```

### 1.2. Формат ошибки

| Код | Смысл | Тело |
|---|---|---|
| 400 | Некорректный запрос | `{ "message": "..." }` |
| 401 | Не аутентифицирован либо токен истёк | `{ "message": "..." }` |
| 403 | Роль не имеет права на операцию | `{ "message": "..." }` |
| 404 | Объект не найден | `{ "message": "..." }` |
| 409 | Конфликт: нарушено ограничение целостности | `{ "message": "..." }` |
| 422 | Ошибка валидации полей | см. ниже |
| 500 | Внутренняя ошибка сервера | `{ "message": "..." }` |

Тело ответа 422:

```json
{
  "message": "Ошибка валидации",
  "errors": {
    "sku": "Артикул «CN8490-002» уже используется",
    "stockAvailable": "Доступно пар не может быть больше общего количества"
  }
}
```

Ключи объекта `errors` совпадают с именами полей модели — это позволяет показать
ошибку прямо в соответствующем поле формы без сопоставления вручную.

### 1.3. Служебные адреса

| Адрес | Назначение |
|---|---|
| `GET /api/__health` | проверка живости: `{ "status": "ok", "time": "..." }` |
| `POST /api/__reset` | восстановление начального набора данных |
| `?__delay=1500` | задержка ответа в миллисекундах — проверка индикатора загрузки |
| `?__fail=500` | принудительный код ошибки — проверка обработки ошибок |

Учебные переключатели работают на любом адресе.

## 2. Аутентификация

С ПР5 включена: все адреса `/api/*`, кроме `/api/auth/*` и служебных, требуют
заголовок `Authorization: Bearer <accessToken>`. Без него или с истёкшим токеном —
**401**, при недостаточной роли — **403**. Роль сервер берёт из базы по
подписанному токену, а не из данных клиента.

| Адрес | Назначение |
|---|---|
| `POST /api/auth/login` | `{login, password}` → `{accessToken, refreshToken, expiresIn, user}` |
| `POST /api/auth/register` | `{login, password, name}` → то же; создаётся роль `client`. Пароль: ≥ 8 символов, цифра, спецсимвол |
| `POST /api/auth/refresh` | `{refreshToken}` → новая пара токенов; старый токен обновления отзывается (одноразовый) |
| `GET /api/auth/me` | текущий пользователь `{id, login, role, name, customerId, blocked}` |
| `POST /api/auth/logout` | `{refreshToken}` — отзыв токена обновления |
| `GET /api/my/orders` | заказы покупателя, связанного с пользователем |
| `POST /api/my/orders/{id}/cancel` | отмена своего заказа в статусе «Новый» |
| `GET /api/users`, `PUT /api/users/{id}` | список пользователей; `{role}` / `{blocked}` — только admin |
| `GET /api/stats` | сводная статистика — только admin |

Срок жизни токена доступа — 15 минут (`--ttl <сек>` меняет его), обновления — 7 дней.

Права по ролям (у каждой роли свой набор операций, а не «больше того же»):

| Операция | client | manager | admin |
|---|:-:|:-:|:-:|
| Чтение кроссовок, брендов, линеек, категорий, отзывов | ✓ | ✓ | ✓ |
| Свои заказы, отмена своего нового заказа | ✓ | | |
| Чтение покупателей и заказов | | ✓ | ✓ |
| Создание, изменение, мягкое удаление (в т.ч. `bulk-delete`) | | ✓ | |
| Физическое удаление `?hard=true`, `restore`, `includeDeleted=true` | | | ✓ |
| Пользователи и роли, статистика | | | ✓ |

Учётные записи: `admin/admin123`, `manager/manager123`, `client/client123`
(client связан с покупателем № 3).

## 3. Ресурсы

Единообразный набор операций доступен для `sneakers`, `brands`, `series`,
`categories`, `customers`, `orders`, `reviews`. Ниже показан на примере моделей.

### `GET /api/sneakers`

| Параметр | Тип | Назначение |
|---|---|---|
| `search` | строка | поиск по названию и артикулу, регистр не учитывается |
| `brandId` | число | фильтр по бренду |
| `seriesId` | число | фильтр по линейке |
| `categoryId` | число | фильтр по категории |
| `yearFrom`, `yearTo` | число | диапазон года выпуска |
| `available` | `true`/`false` | только модели со свободными парами |
| `sort` | строка | поле и направление, например `price,desc` |
| `page` | число | номер страницы, с 1 |
| `size` | число | размер страницы, по умолчанию 10, максимум 100 |
| `includeDeleted` | `true`/`false` | включать логически удалённые, по умолчанию `false` |

Пример: `GET /api/sneakers?search=air&brandId=1&sort=price,desc&page=2&size=10`

Поля сортировки по сущностям:

| Ресурс | Поля `sort` | По умолчанию |
|---|---|---|
| `sneakers` | `name`, `year`, `price`, `stock` | `name,asc` |
| `brands` | `name`, `country`, `year` | `name,asc` |
| `series` | `name`, `country`, `year` | `name,asc` |
| `categories` | `name` | `name,asc` |
| `customers` | `name`, `city`, `bonus` | `name,asc` |
| `orders` | `number`, `date`, `total` | `date,asc` |
| `reviews` | `date`, `rating` | `date,asc` |

Фильтры остальных ресурсов: `series` — `brandId`; `customers` — `city`;
`orders` — `status`, `customerId`, `sneakerId`; `reviews` — `rating`,
`sneakerId`, `customerId`.

### `GET /api/sneakers/{id}`

Ответ `200` — объект модели, `404` — если не найдена или удалена логически.

### `POST /api/sneakers`

Тело:

```json
{
  "name": "Nike Air Max 90",
  "sku": "CN8490-002",
  "year": 2020,
  "price": 14990,
  "brandId": 1,
  "seriesIds": [1],
  "categoryIds": [3, 5],
  "stockTotal": 12,
  "stockAvailable": 7
}
```

Ответ `201` — созданный объект с присвоенным `id`.

### `PUT /api/sneakers/{id}`

Тело такое же, как у `POST`. Ответ `200`.

### `DELETE /api/sneakers/{id}`

Логическое удаление. Ответ `204`. Если на запись ссылаются другие — `409`.

### `DELETE /api/sneakers/{id}?hard=true`

Физическое удаление без возможности восстановления. Ответ `204`.

### `POST /api/sneakers/bulk-delete`

Множественное удаление. Тело: `{ "ids": [3, 7, 11] }`. Ответ `200`:
`{ "deleted": 2 }` — записи со ссылками пропускаются.

### `POST /api/sneakers/{id}/restore`

Восстановление логически удалённой записи. Ответ `200`.

## 4. Модели

На запись уходят идентификаторы связей, а в ответе рядом с ними лежат развёрнутые
объекты. Это стандартная для REST ситуация, и разбор на клиенте читает
идентификаторы, а развёрнутые объекты игнорирует.

### `Sneaker`

```json
{
  "id": 1,
  "name": "Nike Air Max 90",
  "sku": "CN8490-002",
  "year": 2020,
  "price": 14990,
  "brandId": 1,
  "seriesIds": [1],
  "categoryIds": [3, 5],
  "stockTotal": 12,
  "stockAvailable": 7,
  "deletedAt": null,
  "brand": { "id": 1, "name": "Nike", "country": "США" },
  "series": [{ "id": 1, "name": "Air Max" }],
  "categories": [{ "id": 3, "name": "Повседневные" }]
}
```

### `Brand`

`{ id, name, country, foundedYear, deletedAt }`

### `Series`

`{ id, name, brandId, country, launchYear, deletedAt, brand }`

### `Category`

`{ id, name, description, deletedAt }`

### `Customer`

`{ id, firstName, lastName, email, phone, city, card, deletedAt, fullName }`,
где `card` — связь один к одному либо `null`:

```json
{ "number": "10000001", "level": "Золотая", "bonusPoints": 2400, "issuedAt": "2023-05-12T09:00:00.000Z" }
```

Уровни карты: `Серебряная`, `Золотая`, `Платиновая`.

### `Order`

`{ id, number, customerId, sneakerId, size, quantity, price, status, createdAt, deletedAt, total, customer, sneaker }`

Статусы: `Новый`, `Оплачен`, `Отправлен`, `Доставлен`, `Отменён`.
Размеры: от 36 до 46.

### `Review`

`{ id, customerId, sneakerId, rating, text, createdAt, deletedAt, customer, sneaker }`

## 5. Проверки на сервере

Сервер проверяет то, что клиент проверить не может.

| Ресурс | Проверка | Код |
|---|---|---|
| `sneakers` | артикул уникален | 422, поле `sku` |
| `sneakers` | доступно пар не больше общего количества | 422, поле `stockAvailable` |
| `sneakers` | бренд, линейки и категории существуют | 422 |
| `brands` | название уникально | 422, поле `name` |
| `categories` | название уникально | 422, поле `name` |
| `customers` | почта уникальна и имеет верный формат | 422, поле `email` |
| `customers` | номер карты из 8–16 цифр, уровень из списка | 422, поля `cardNumber`, `cardLevel` |
| `orders` | номер заказа уникален | 422, поле `number` |
| `orders` | заказ на модель без свободных пар | **409** |
| любой | удаление записи, на которую ссылаются другие | **409** |

Ссылочная целостность: бренд удерживают модели и линейки, линейку и категорию —
модели, покупателя и модель — заказы и отзывы. В сообщении 409 указано число
связанных записей.

## 6. Требования к серверу для работы с Flutter Web

### 6.1. CORS

Браузер не отдаст ответ коду приложения, если сервер не разрешил источник явно.
Сервер отвечает на каждый запрос заголовками:

```
Access-Control-Allow-Origin: http://localhost:5555
Access-Control-Allow-Methods: GET, POST, PUT, PATCH, DELETE, OPTIONS
Access-Control-Allow-Headers: Content-Type, Authorization
Access-Control-Max-Age: 86400
Vary: Origin
```

Отдельно обрабатывается предварительный запрос `OPTIONS` с ответом `204`:
без него не заработает ни один запрос с телом или заголовком `Authorization`.

### 6.2. Фиксированный порт клиента

Клиент запускается только с фиксированным портом, иначе источник меняется
при каждом запуске и сервер начнёт отклонять запросы:

```bash
flutter run -d chrome --web-port=5555
```

Разрешённый источник задаётся при запуске сервера параметром `--origin`.

### 6.3. Изоляция данных

Данные хранятся в памяти процесса и сбрасываются при перезапуске сервера
либо запросом `POST /api/__reset`.
